# MIGRATION NOTES

Ключевые архитектурные решения при доведении проекта до production. Кратко: бэкенд переписан
начисто в пакет `app/`, тяжёлый веб-фронт (шаблон Vercel AI Chatbot) удалён и заменён
минимальным Ч/Б чатом, секреты вынесены в `.env`, добавлены `/admin`, краулер и `eval/`.
Telegram-бот сохранён и переключён на общий бэкенд.

## Удалено

- **`web/ai-chatbot/`** (весь шаблон Vercel AI Chatbot: Next.js + Drizzle/Postgres + NextAuth +
  артефакты + редакторы кода + виджеты). Несовместим с требованием «простой Ч/Б чат» и
  «простота хостинга»: тянул БД, авторизацию и десятки зависимостей ради функций, которые
  продукту не нужны. Заменён одним файлом `frontend/chat.html` (vanilla HTML/CSS/JS).
  Деплой через Vercel (`.vercel/`, `vercel.json`) тоже снят — новая система деплоится как
  один сервис FastAPI, отдающий и API, и статику.
- **`web/docs/`** (старый тёмный PDF-вьюер на шаблонах + `site.py`). Имел баг с двойным
  `#fragment` (`...#page=N#view=FitH`) и тёмную палитру. Не нужен: ссылки на источники теперь
  ведут прямо на `/files/<doc>.pdf#page=N`, что нативно открывает нужную страницу в браузере.
- **`api/`** целиком:
  - `api/rag_engine.py` — рабочий, но переусложнённый: ручной ремонт JSON от модели, эвристики
    `harvest_items_from_chunks`, `extract_abcd_scores` (парсинг «A,B,C,D» из вопроса) — узкие
    костыли под конкретные кейсы. Переписан в `app/rag.py` (чистый retrieve → промпт → ответ).
  - `api/server.py` — заменён на `app/server.py` (добавлены `/query`, `/admin*`).
  - `api/config.py` — **содержал секреты в коде** (Yandex key, Telegram token); удалён, секреты
    перенесены в `.env`. Файл был в `.gitignore`, но хранить ключи в коде недопустимо.
  - `api/index_letovo/`, `api/docs/` — индекс пересобран в `data/index/`, PDF скопированы в
    `data/docs/` (см. «Сохранено»).
- **`scipy`, `aiofiles`** из зависимостей — больше не используются (старый код считал косинус
  через `scipy.spatial.distance.cdist`; новый store — на чистом numpy).

## Переписано

- **Бэкенд → пакет `app/`**: `config` (из `.env`), `embeddings`, `llm`, `store`, `ingest`,
  `indexer`, `rag`, `crawl`, `server`, `prompts`. Чёткое разделение ответственности.
- **Системный промпт** (`app/prompts.py`): вместо требования вернуть JSON в тегах `<json>`
  (и последующего ремонта парсинга) модель теперь выдаёт обычный текст ответа, а блок
  «Источники» собирается детерминированно из retrieval — это гарантирует валидные ссылки
  (метрика ≥95%). Зашиты точные строки отказов:
  - нет данных → «В документах школы нет данных по этому вопросу.»
  - вне зоны → вежливый отказ с напоминанием о зоне.
- **Контракт API**: основной эндпоинт `/query` (старый `/ask` оставлен как алиас для
  совместимости). Ответ содержит `answer`, `sources`, `status` и готовый `text` (с блоком
  источников) — удобно боту.
- **Telegram-бот** (`telegram/bot.py`): сохранена вся обвязка (rate-limit, дневной лимит,
  чанкинг длинных сообщений, inline-кнопки), но:
  - переключён с `/ask` на общий `/query`;
  - токен и URL бэкенда берутся из `.env`;
  - отправка переведена с Markdown на **обычный текст** — ответы могут содержать `*`, `_`, `[`,
    которые ломают парсинг Markdown в Telegram (ошибка 400); голые URL Telegram линкует сам,
    плюс к каждому источнику добавлена inline-кнопка (раньше кнопка показывалась только при
    ровно одном источнике).

- **Обвязка Telegram-бота** — логика лимитов и UX (см. выше).

## Решения, которые стоит знать

1. **LLM/эмбеддинги — OpenAI (ChatGPT) API.** Изначально проект был на Yandex Cloud, но по
   решению заказчика (2026-05-28) Yandex убран полностью и заменён на OpenAI: чат —
   `OPENAI_MODEL` (gpt-4o-mini), эмбеддинги — `OPENAI_EMBED_MODEL` (text-embedding-3-small,
   1536-dim, батч-запросы). `yandex-cloud-ml-sdk` удалён из зависимостей, `YANDEX_*` — из
   конфига. `OPENAI_BASE_URL` позволяет указать любой OpenAI-совместимый эндпоинт. Смена модели
   эмбеддингов требует пересборки индекса (в `store.search` есть guard на несовпадение
   размерности — не падает, а возвращает «нет результатов» до реиндексации).
2. **OpenAI вызывается через `requests`, а не через официальный SDK** (`app/openai_rest.py`).
   Связка openai-SDK + httpx ломает построение URL на Python 3.14 (`UnsupportedProtocol` при
   склейке base_url с относительным путём — воспроизводится и на openai 1.x, и на 2.x).
   `requests` с абсолютными URL работает везде (3.14 dev и 3.12 в Docker). `openai` убран из
   зависимостей.
3. **Vector store — numpy flat-cosine, а не Qdrant/Chroma.** При ~4–5к чанках brute-force
   мгновенный и не требует отдельного сервиса. Инкрементальная переиндексация (добавить/удалить
   документ без полного пересчёта) реализована в `app/store.py`.
4. **Корпус: индексируем только нормативные документы.** Краулер собрал 280 PDF с letovo.ru, из
   них 233 с текстом. Но 4 ООП + ~25 рабочих программ (учебные программы на тысячи страниц)
   давали 86 документов = 21 тыс. из 25.7 тыс. чанков и засоряли поиск (нормативные ответы тонули
   среди учебных программ). По `INDEX_EXCLUDE` (regex) они исключены → индекс = **147 нормативных
   PDF / ~4.4 тыс. чанков**. PDF и `_sources.json` сохранены — это решение обратимо через `.env`.
5. **Источники указывает модель, а собирает код.** Модель в конце ответа возвращает строку
   `ИСТОЧНИКИ: N` (номера использованных блоков `[Источник N]`); код парсит её и строит ссылки на
   страницы PDF из этих блоков. Это даёт точную атрибуцию (раньше детерминированный «топ по
   косинусу» мог процитировать релевантный по эмбеддингу, но не использованный документ) при
   гарантии валидности ссылок. На отказах строка не добавляется → источников нет.
6. **Релевантностный гейт `OFFTOPIC_GATE` отключён (0) для OpenAI-эмбеддингов.** У Yandex
   off-topic чётко отделялся по косинусу (0.23–0.28 vs 0.42+), и гейт работал. У
   `text-embedding-3-small` на большом корпусе off-topic (0.43–0.48) и тематические вопросы
   (0.42–0.64) НЕ разделяются — порог невозможен без потери реальных вопросов. Отказ на off-topic
   делает `gpt-4o-mini` по промпту (модель сильнее yandexgpt-lite и надёжно отказывает).

## Проверка

`python -m eval.run` на контрольном наборе из 18 вопросов (корпус 147 PDF, OpenAI): точность
**94%**, доля валидных ссылок **100%**, средняя задержка **~6.5 c**, **0** галлюцинаций на
вопросах без данных. Все целевые метрики раздела 5 ТЗ достигнуты.
